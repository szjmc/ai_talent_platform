# 笔试题库检索与对接

知识库提供两个接口：POST /api/v1/knowledge/questions/upload（上传并导入笔试题库）和POST /api/v1/knowledge/questions/search（按技术、等级和题型查询笔试题库）。沿用Bearer Token、knowledge:read权限、ApiResponse统一响应。Router仅接收参数，Service编排，Repository查询MySQL，Adapter访问Milvus，共享现有连接生命周期。

## 数据与索引

- 新增MySQL表question_bank_questions；id为接口返回的question_id。bank_id是业务侧题库编号；external_id是来源题号，两者组合唯一，重复导入更新同一题而非新增重复记录。
- 新增Milvus集合question_bank_vectors，名称由MILVUS_COLLECTION_QUESTIONS配置。与knowledge_chunks、assessment_chunks等已有集合隔离，不修改既有Schema。
- 一道题一条向量，文本包括技术、等级、题型、知识点、完整题干和选项，不包括答案和解析，不使用文档semantic分块。
- 使用LangChain原生OpenAIEmbeddings或OllamaEmbeddings，继承现有LLM_EMBED_PROVIDER、LLM_EMBED_MODEL、供应商密钥/地址、EMBEDDING_DIM配置。兼容协议供应商发送原始文本；维度以模型实际输出为准。
- permission_scope支持public/dept/private；默认private。private仅归属人及超级管理员可见，dept额外允许同部门用户，public允许有knowledge:read权限的用户读取。
- 本接口不创建试卷、不修改assessment_questions。测评模块确定题目后自行保存题干、选项、答案和来源版本的快照。

## Swagger上传导入

接口名称：上传并导入笔试题库。路径：POST /api/v1/knowledge/questions/upload。需要Bearer Token和knowledge:manage权限。使用multipart/form-data，在file选择JSON文件；sync_index默认true，同步等待本批向量索引处理，不扫描其他题库任务。普通知识文档仍使用/docs/upload。

文件格式与scripts/question_bank.example.json一致，每题携带技术、等级、题型和标准答案；判断答案为true/false，填空答案为每个空的候选答案列表。整批先校验再写入；重复bank_id+external_id更新同一题，不生成重复题目。非管理员不能覆盖其他用户的题目或导入其他部门，题目归属人为登录用户。

响应data包含imported_count、question_ids、sync_requested、indexed_count、failed_count、pending_count和可选sync_error。导入事务失败会整体回滚，不调用向量服务；导入已提交后的索引失败保留数据并报告状态，不能据HTTP 200认定全部索引成功。重复上传同一JSON可重试本批索引；sync_index=false时只提交数据库，后续执行sync脚本。上传文件用于解析结构化题目，本接口不另外保存原始JSON文件到文件中心。

## 初始化和脚本导入

在项目根目录，使用项目依赖齐全的Python环境执行：

~~~powershell
python scripts/question_bank.py init
python scripts/question_bank.py import scripts/question_bank.example.json --owner-id 1 --dry-run
python scripts/question_bank.py import scripts/question_bank.example.json --owner-id 1 --sync
~~~

owner-id必须替换为已存在的归属用户ID。示例只有3道合成题，用于演示选择、判断、填空；不自动导入。init仅幂等创建新增表和集合，没有删除或重建选项；已存在的不兼容集合会明确报错。

初级/中级/高级分别为beginner/intermediate/advanced；题型为single/multiple/true_false/fill_blank/text/coding。单选答案为选项key，多选为key列表，判断为JSON布尔值，填空为每个空的可接受答案列表（如[["yield"],["list","列表"]]），简答及编程为参考答案文本。每题必须显式给出等级，不依赖模型推断。

导入整个JSON先校验再写入，最大10000题/文件；同题库来源题号不得在同文件内重复。导入前可dry-run，无数据库、Milvus和模型请求。初次导入默认published、private，可在JSON中显式指定状态与范围。

## 调用示例

~~~json
{
  "technology": "python",
  "difficulty": "intermediate",
  "query": "生成器与异步编程",
  "counts": {"single": 5, "true_false": 3, "fill_blank": 2},
  "bank_ids": [1],
  "exclude_question_ids": [],
  "include_answers": false
}
~~~

query省略或为空时按MySQL条件随机抽题，不调用模型或Milvus；有query则将知识点查询向量化一次，按已授权题目ID白名单分批进行Milvus语义检索、合并排名、回表核对当前版本。技术、等级、题型、bank_ids、排除ID不会被放宽。每个题型可以请求0至100题，总数须为1至100。

响应data包含mode、requested_count、returned_count、shortage和items。shortage仅包含缺题的题型与缺额。items包含question_id、bank_id、external_id、content_version、technology、difficulty、question_type、knowledge_points、stem、options，语义模式另有score（余弦相似度）。随机模式不返回score。

默认不返回answer和analysis；include_answers=true须额外拥有assessment:manage权限，否则403。评分或组卷的可信同事服务可使用该权限调用，考生端不能使用该服务Token。

## 索引维护与重试

~~~powershell
python scripts/question_bank.py sync
python scripts/question_bank.py sync --force
~~~

修改JSON后重复import会递增内容版本，标记pending，sync重试pending/error记录；更换向量模型/地址/维度也需要sync。状态改为disabled/draft或逻辑删除的题目同步时移除对应题目向量，不影响其他题目或集合。--force逐题覆盖本题库向量，不清空集合。

MySQL先提交题目及待同步状态，向量成功写入后才标记indexed；失败记录error及异常类型，下次sync可重试。查询仅使用模型签名、内容版本一致的索引，回表再次核对；未同步或失败题目不会被语义查询返回，但无query的SQL查询仍可读取已发布题目。索引同步脚本用MySQL命名锁防止并发乱序覆盖。

第一版不新增常驻后台worker；部署时可由现有作业调度定期执行sync。直接改数据库时必须递增content_version并设置index_status=pending，避免跳过同步；建议通过导入脚本更新。修改向量维度需配置新的独立集合名并初始化，禁止重建原有集合。

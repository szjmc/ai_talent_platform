# 公共层使用手册（Common Layer Manual）

> 面向对象：**所有参与后端开发的同学**。
> 目的：公共层（配置 / 应用装配 / 数据库 / 响应 / 异常 / 认证 / 权限 / Repository）已经统一实现，
> 你只需要「按约定调用」，不要重复造轮子，也不要在业务代码里再做一套响应/异常/权限。

版本：v1.0.0 · 对应代码分支：`arena/2ad4a4ac-ai-talent-platform`

## 一、5 分钟跑起来

### 0. 前置依赖

平台**不使用 SQLite**，启动前需要两个数据库服务：

| 数据库 | 版本 | 作用 | 默认连接 |
| --- | --- | --- | --- |
| MySQL | 8.0+ | 业务主库（用户/组织/岗位/人才/测评等） | `127.0.0.1:3306`，驱动 `mysql+aiomysql` |
| PgSQL | 15+ | 分析/时序库（海量履历、测评历史、分析宽表，Vanna NL2SQL 查询库） | `127.0.0.1:5432`，驱动 `postgresql+asyncpg` |

没有本地数据库时，可用项目自带的 `docker-compose.yml` 一键拉起（账号密码与 `.env.example` 默认值一致）：

```bash
docker compose up -d                     # MySQL 8 + PgSQL 16
docker compose --profile cache up -d     # 需要 Redis 时再加
```

```bash
cd ai_talent_platform                 # 项目根目录（含 main.py）
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env                  # 按本地实际填写 DB_* / PGSQL_* 账号密码

python scripts/init_db.py             # MySQL 建库建表 + 内置角色 + PgSQL 建分析库
python scripts/create_admin.py -u admin -p Admin@12345   # 创建超管
python scripts/seed_data.py           #（可选）演示部门树与测试账号

python main.py                        # 启动开发服务器
```

启动日志会打印两个库的连通结果；连不上时不会崩溃（开发模式），
而是给出可读原因，`GET /health/ready` 也能看到同样的诊断（含修复建议）。

启动后：

| 地址 | 说明 |
| --- | --- |
| http://127.0.0.1:8000/docs | Swagger（点右上角 Authorize 填 access_token 调试） |
| http://127.0.0.1:8000/redoc | ReDoc |
| http://127.0.0.1:8000/health | 存活探针 |
| http://127.0.0.1:8000/health/ready | 就绪探针（检查数据库） |
| http://127.0.0.1:8000/api/v1/system/info | 框架装配自检（表、驱动、已实现模块） |

### 数据库配置（.env）

```dotenv
# MySQL 业务主库
DB_DRIVER=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=root
DB_PASSWORD=你的密码
DB_NAME=ai_talent_platform

# PgSQL 分析库
PGSQL_ENABLED=true
PGSQL_HOST=127.0.0.1
PGSQL_PORT=5432
PGSQL_USER=postgres
PGSQL_PASSWORD=你的密码
PGSQL_DB=ai_talent_analytics
```

`python scripts/init_db.py` 会自动 `CREATE DATABASE IF NOT EXISTS`（MySQL 字符集 utf8mb4；
PgSQL 分析库不存在时自动创建）。`PGSQL_ENABLED=false` 时分析类功能降级为「仅统计 MySQL」，
业务接口不受影响。

**跑测试**：`pytest -q`（使用独立 MySQL 测试库 `ai_talent_platform_test`，默认自动建库建表；
可用 `TEST_DB_NAME=xxx` 覆盖；库不可用时用例会 skip 并打印连接目标）。

## 三、统一响应格式（core/response.py）

### 3.1 结构

```json
{
  "code": 200,
  "message": "success",
  "data": { "id": 1, "name": "张三" },
  "trace_id": "0a10f00426934e71"
}
```

| 字段 | 含义 |
| --- | --- |
| `code` | 业务状态码，**与 HTTP 状态码同源**（200 成功） |
| `message` | 中文提示语，可直接展示给用户 |
| `data` | 业务数据，可为 `null` / 对象 / 数组 / 分页结构 |
| `trace_id` | 请求链路 ID（也写在响应头 `X-Trace-Id`），排查问题时报给后端 |

### 3.2 Router 里怎么用

```python
from app.core.response import success

return success(data=obj, message="创建成功")          # 成功
return success(data=page_result)                      # 分页
# 失败不要自己 return，直接抛异常（见第四节）
```

### 3.3 Swagger 响应声明

```python
from app.schemas.common import SuccessResponse, COMMON_ERROR_RESPONSES

@router.get("", response_model=SuccessResponse[UserResponse], responses=COMMON_ERROR_RESPONSES)
```

## 四、异常体系（core/exceptions + exception_handlers）

**铁律：业务失败就 `raise`，不要 `return {"code": 500}`。**

```python
from app.core.exceptions import (
    ParamError, BusinessRuleError, AuthError, PermissionDeniedError,
    NotFoundError, DuplicateError, AIError, FileError,
)

if await repo.exists_username(db, data.username):
    raise DuplicateError("登录名已被占用")
```

内置异常与错误码：

| 异常 | code | HTTP | 场景 |
| --- | --- | --- | --- |
| `ParamError` | 1001 | 422 | 业务层二次校验失败 |
| `BusinessRuleError` | 1002 | 400 | 违反业务规则 |
| `AuthError` | 2001 | 401 | 未登录 / 凭证无效 |
| `TokenExpiredError` | 2002 | 401 | 令牌过期 |
| `CredentialsError` | 2003 | 401 | 用户名或密码错误 |
| `PermissionDeniedError` | 2004 | 403 | 权限不足 |
| `AccountDisabledError` | 2005 | 401 | 账号禁用 |
| `AccountLockedError` | 2006 | 401 | 登录失败锁定 |
| `NotFoundError` | 3001 | 404 | 资源不存在 |
| `DuplicateError` | 3002 | 409 | 唯一键冲突 |
| `DataConflictError` | 3003 | 409 | 乐观锁冲突 |
| `SystemError` | 5000 | 500 | 系统内部错误 |
| `ExternalServiceError` | 5001 | 502 | 外部服务调用失败 |
| `AIError` | 5002 | 502 | AI 能力异常 |
| `FileError` | 5003 | 400 | 文件处理失败 |

全局处理器（已自动注册）负责把：

- `BusinessException` → 标准响应（warning 日志，不打堆栈）
- `RequestValidationError` → 422，`data.errors` 为 `[{field, message, type}]`
- `StarletteHTTPException` → 401/404/405 等统一包装
- 未捕获 `Exception` → 500 + 完整堆栈写日志（对外隐藏细节）

新增异常：继承 `BusinessException` 并设置 `code / status_code / message` 即可，无需改处理器。

## 五、数据库使用（infrastructure/database）

### 5.1 拿 Session

```python
from app.core.dependencies import DbSession          # = Annotated[AsyncSession, Depends(get_db)]

@router.get("/x")
async def x(db: DbSession):
    ...
```

或在 Service 构造函数里注入：

```python
class TalentService:
    def __init__(self, db: AsyncSession):
        self.db = db
```

**不要自己 `async_sessionmaker()` / `Session()`**，也不要在 Repository 里 `commit()`。

### 5.2 事务规则

- 一次 HTTP 请求 = 一个事务：`get_db()` 成功自动 `commit`，异常自动 `rollback`；
- 需要局部事务 / 嵌套事务：

```python
from app.infrastructure.database.transaction import transaction

async with transaction(db):        # 外层已有事务时自动用 SAVEPOINT
    await repo_a.update(...)
    await repo_b.create(...)
```

- 死锁自动重试（幂等操作）：

```python
from app.infrastructure.database.transaction import retry_on_deadlock

@retry_on_deadlock(max_attempts=3)
async def upsert_stat(...): ...
```

### 5.3 脚本 / 后台任务里用 Session

```python
from app.infrastructure.database.session import session_scope

async with session_scope() as db:
    ...
```

### 5.4 表结构管理

- 开发期：`python scripts/init_db.py`（`create_all`），lifespan 也会自动建表（非 prod）；
- 生产：使用 Alembic 迁移（`migrations/`），**不要**依赖 `create_all`。

## 六、ORM 基类（models/base.py）

```python
from app.models.base import BaseModel

class Talent(BaseModel):
    __tablename__ = "talents"
    name: Mapped[str] = mapped_column(String(64), nullable=False)
```

`BaseModel` 已自带：

| 字段 | 说明 |
| --- | --- |
| `id` | 自增主键（MySQL BIGINT） |
| `created_at` / `updated_at` | 数据库默认值 + ORM 默认值，更新时自动维护 |
| `is_deleted` / `deleted_at` | 逻辑删除，`soft_delete()` / `restore()` |
| `created_by` / `updated_by` | 数据归属（数据范围校验用） |
| `version` | 乐观锁版本号，Repository 更新时自动 +1 |

约定：

1. 业务表一律继承 `BaseModel`；纯关联表可只继承 `Base` + `TimestampMixin`；
2. 新增模型后**必须**在 `app/models/__init__.py` 导入，否则 `create_all` / Alembic 看不到表；
3. 时间统一存本地时间（`DateTime`），JWT 用 UTC 时间戳；
4. `__table_args__` 加中文 `comment`，便于 DBA 阅读。

## 七、Repository 使用（repositories/base.py）★重点

### 7.1 你只需要声明 4 行

```python
from app.repositories.base import BaseRepository
from app.models.talent import Talent

class TalentRepository(BaseRepository[Talent]):
    model = Talent
    filterable_fields = {"organization_id", "education", "status"}   # 允许精确筛选
    searchable_fields = {"name", "mobile", "current_position"}       # 关键字模糊搜索
    sortable_fields = {"id", "created_at", "name"}                   # 允许排序
    default_order = "-created_at"                                    # "-" 表示倒序
```

### 7.2 开箱即用的方法

| 分类 | 方法 |
| --- | --- |
| 查询 | `get_by_id` / `get_by_id_or_404` / `get_one` / `get_by_field` |
| 列表 | `list`（filters + keyword + 排序 + limit/offset）、`list_all` |
| 分页 | `paginate(db, page_params, filters=..., keyword=...)` → `PageResult` |
| 统计 | `count`、`exists` |
| 写入 | `create`（对象 / dict / kwargs 三种写法）、`create_many` |
| 更新 | `update(db, obj, dict)`、`update_by_id`、`bulk_update` |
| 删除 | `delete`（默认逻辑删除）、`delete_by_id`、`hard_delete` |

```python
repo = TalentRepository()

talent = await repo.get_by_id_or_404(db, 1)
items  = await repo.list(db, filters={"education": "本科"}, keyword="张", limit=20)
page   = await repo.paginate(db, page_params, keyword="AI")
await repo.create(db, {"name": "张三", "education": "本科"})
await repo.update(db, talent, {"status": "active"})
await repo.delete(db, talent)                   # 逻辑删除
```

### 7.3 白名单很重要（安全）

`filters` 只接受 `filterable_fields` 里的字段，`order_by` 只接受 `sortable_fields` 里的字段，
非法字段会被**静默忽略并回落默认排序**。这样即使参数来自前端，也不可能造成 SQL 注入或全表乱序。

### 7.4 复杂查询写在具体 Repository

```python
class TalentRepository(BaseRepository[Talent]):
    model = Talent
    ...
    async def search_by_skills(self, db, skills: list[str]) -> list[Talent]:
        stmt = select(Talent).where(Talent.is_deleted.is_(False))
        for skill in skills:
            stmt = stmt.where(func.json_contains(Talent.skill_tags, f'"{skill}"'))
        return list((await db.execute(stmt)).scalars().all())
```

**Repository 里不要有业务判断**（「这个人是否符合岗位」属于 Service）。

## 八、分页（core/pagination.py）

```python
from app.core.pagination import PageParams, build_page_result

@router.get("")
async def list_users(
    page: PageParams = Depends(),          # 自动解析 page / page_size / order_by / order
    service: UserService = Depends(get_user_service),

    result = await service.page_list(page)
    return success(data=build_page_result(result.items, result.total, page))

返回结构：

{ "items": [], "total": 128, "page": 1, "page_size": 20, "pages": 7 }
```

## 九、认证与权限（core/security + permissions + dependencies）★重点

### 9.1 密码

```python
from app.core.security import hash_password, verify_password

user.password_hash = hash_password("明文密码")      # bcrypt，自带盐
ok = verify_password("明文密码", user.password_hash)
```

### 9.2 JWT

```python
from app.core.security import create_access_token, create_refresh_token, decode_token

token = create_access_token(user.id, username=user.username, roles=user.role_codes)
payload = decode_token(token)          # 失败自动抛 AuthError / TokenExpiredError
```

### 9.3 Router 中拿当前用户

```python
from app.core.dependencies import CurrentUser, OptionalUser

@router.get("/me")
async def me(user: CurrentUser):        # 未登录自动 401
    ...

@router.get("/public")
async def public(user: OptionalUser):   # 允许匿名，登录时能拿到用户
    ...
```

### 9.4 权限控制

```python
from fastapi import Depends
from app.core.dependencies import require_permission
from app.core.permissions import PermissionEnum

@router.post("", dependencies=[Depends(require_permission(PermissionEnum.TALENT_CREATE))])
async def create_talent(...): ...

@router.get("", dependencies=[Depends(require_permission("talent:read", "talent:update", require_all=True))])
```

- 权限码规范：`模块:动作`（`talent:read`、`position:manage`、`analytics:export`）；
- 角色 → 权限映射集中在 `core/permissions.py` 的 `ROLE_PERMISSIONS`，需要新增权限码就加进 `PermissionEnum`；
- `super_admin` 拥有通配符 `*`；`is_superuser=True` 的用户跳过校验；
- 角色级校验：`Depends(require_roles("hr", "admin"))`。

### 9.5 数据范围（行级权限）

```python
from app.core.permissions import get_data_scope, check_data_scope, DataScopeEnum

scope = get_data_scope(user.role_codes)      # all / dept_sub / dept / self
check_data_scope(user.role_codes, owner_id=obj.created_by, current_user_id=user.id)
```

列表查询时由 Service 把范围条件翻译成 Repository 的 `extra_where`（例如按 `organization_id in (...)` 过滤）。

### 9.6 前端怎么对接

1. `POST /api/v1/auth/login` 拿 `access_token` + `refresh_token`；
2. 之后每个请求带 `Authorization: Bearer <access_token>`；
3. 401（code 2001/2002）→ 用 `POST /api/v1/auth/refresh` 换新 token；
4. `GET /api/v1/auth/me` 拿 `roles` / `permissions` 渲染菜单与按钮。

## 十一、新增一个业务模块的标准流程（照抄即可）

以「岗位管理」为例，顺序固定：**Model → Repository → Schema → Service → Router → 注册**。

### 1) Model（`app/models/position.py`）

```python
class Position(BaseModel):
    __tablename__ = "positions"
    __table_args__ = {"comment": "岗位表"}
    title: Mapped[str] = mapped_column(String(128), nullable=False, index=True)
    ...
```

到 `app/models/__init__.py` 里 `from app.models.position import Position` 并加入 `__all__`。

### 2) Repository（`app/repositories/position_repository.py`）

```python
class PositionRepository(BaseRepository[Position]):
    model = Position
    filterable_fields = {"organization_id", "level", "status"}
    searchable_fields = {"title", "code"}
    sortable_fields = {"id", "created_at", "title"}
```

### 3) Schema（`app/schemas/position.py`）

`PositionCreate` / `PositionUpdate` / `PositionQuery` / `PositionResponse`，
写模型继承 `BaseSchema`（拒绝未知字段），读模型继承 `ORMModel`（`from_attributes`）。

### 4) Service（`app/services/position_service.py`）

```python
class PositionService:
    def __init__(self, db: AsyncSession):
        self.db = db
        self.repo = PositionRepository()

    async def create_position(self, data: PositionCreate) -> Position:
        if await self.repo.exists(self.db, {"code": data.code}):
            raise DuplicateError("岗位编码已存在")
        return await self.repo.create(self.db, data.model_dump())
```

### 5) Router（`app/routers/position_router.py`）

```python
router = APIRouter(prefix="/positions", tags=["岗位管理"], responses=COMMON_ERROR_RESPONSES)

@router.post("", response_model=SuccessResponse[PositionResponse],
             dependencies=[Depends(require_permission(PermissionEnum.POSITION_MANAGE))])
async def create_position(data: PositionCreate, service: PositionService = Depends(get_position_service)):
    return success(data=await service.create_position(data), message="创建成功")
```

### 6) 注册总路由（`app/routers/router.py`）

把 `_STUB_MODULES` 里的 `positions` 占位删掉，改成：

```python
from app.routers.position_router import router as position_router
api_router.include_router(position_router)
```

### 7) 自检清单

- [ ] `/docs` 能看到新接口，响应模型正确；
- [ ] 无 Token → 401（code 2001）；权限不足 → 403（code 2004）；
- [ ] 参数错误 → 422 且 `data.errors` 可读；
- [ ] 响应不含敏感字段（`password_hash`、身份证等）；
- [ ] 写操作有审计/日志；
- [ ] 新增模型已注册，`/api/v1/system/info` 的 `orm_tables` 里能看到；
- [ ] `pytest -q` 通过，并补一个集成用例。

## 十三、常见问题（FAQ）

**Q1：启动报 `ModuleNotFoundError: No module named 'app'`**
在项目根目录（含 `main.py`）执行，或用 `uvicorn main:app`；`main.py` 已自动把根目录加入 `sys.path`。

**Q2：MySQL 连接失败**
检查 `.env` 的 `DB_*`；`python scripts/init_db.py` 会先建库。`/health/ready` 可快速确认。

**Q3：报 `MissingGreenlet`**
异步会话里触发了懒加载（例如直接给 `user.roles = [...]`）。解决方式：
先用 `await db.refresh(user, attribute_names=["roles"])`，或统一走 `UserRepository.set_roles()`；
查询关系时用 `lazy="selectin"` 或显式 `selectinload`。

**Q4：ResponseValidationError**
`response_model` 与返回结构不匹配。分页接口返回的是 `PageResult`（不是 `list`）；
ORM 对象要用 `ORMModel` 子类并在 Schema 里声明 `from_attributes=True`。

**Q5：为什么接口返回 422 但看不出哪个字段错**
看响应 `data.errors`：`[{"field": "password", "message": "密码必须同时包含字母和数字", "type": "value_error"}]`。

**Q6：改了模型但表没变**
`create_all` 只建不改。开发期用 `python scripts/init_db.py --drop`（会清空数据）；
正式流程用 Alembic 生成迁移脚本。

**Q7：Swagger 里接口需要 Token 怎么调**
先调 `/auth/login`，复制 `access_token`，点右上角 **Authorize** 粘贴（可保存到刷新后）。

**Q8：占位接口返回 501 是什么**
尚未实现的模块（talents / resumes / …）目前挂的是占位路由，返回 501 + 负责的代码文件位置。
实现后在 `routers/router.py` 里替换 include 即可。

**Q9：能不能直接在 Router 里写 `select(...)`**
不行。查询写进 Repository，业务判断写进 Service，Router 只做参数接收与响应包装。

**Q10：限流、跨域在哪里改**
`app/core/middleware.py`（限流上限/窗口）与 `settings.CORS_ORIGINS`。
多实例部署时把进程内限流替换为 Redis 实现（`infrastructure/cache/redis.py` 已备好 `incr_with_ttl`）。

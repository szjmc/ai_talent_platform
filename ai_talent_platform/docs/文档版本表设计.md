# 文档版本表（仅新增一表）

新表：knowledge_revisions。现有knowledge_docs、knowledge_chunks、files、users等表不增删字段、不执行ALTER。

## 外键关联

| 新表字段 | 关联 | 用途 |
|---|---|---|
| doc_id | knowledge_docs.id | 同一业务文档的多个版本 |
| parent_revision_id | knowledge_revisions.id | 基于哪一版编辑，Service校验属于同一文档 |
| source_file_id | files.id | 上传原件 |
| file_id | files.id | 该版本文件，编辑后生成Word |
| body_file_id | files.id | 完整可编辑正文文件 |
| preview_file_id | files.id | 切片预览快照文件 |
| index_manifest | files.id | 发布索引清单文件，关联该版切片ID、模型与集合 |
| published_by | users.id | 发布人 |

继承的created_by/updated_by沿用原项目逻辑关联用户的约定，不改变公共基类。新模型单向relationship集中定义在本文件，不修改旧模型。文件外键SET NULL避免物理删除旧文件时阻断原有调用，但版本文件应由业务保留策略保护；文档物理删除CASCADE删除版本，正常归档应使用软删除保留历史。

## 版本与并发

revision_no是对外业务版本号，同文档唯一；继承version用于乐观锁。status区分draft/previewed/publishing/published/archived/failed。active_marker是新表内部生成列，未软删的published记录为1，其余为NULL；联合唯一约束(doc_id, active_marker)保证每份文档最多一个生效版本。生成表达式不引用外键字段，兼容MySQL级联约束限制。发布在同一事务内先归档旧版再发布新版；Service已实现乐观锁、来源版本归属、预览失效及竞争发布校验。当前采用同步发布，失败回滚后仍保留previewed状态供重试，publishing/failed作为后续异步任务状态预留。

title/category保存版本快照；content_hash、preview_hash防止正文和切片预览不一致。正文、文件、预览及索引清单存MinIO并登记files，不把全文写入审计日志。当前切片表结构保持不变，版本切片追溯通过清单文件实现。

## 执行

模型：app/models/knowledge_revision.py。只在models/__init__.py增加模型注册，既有表定义不变。

导出SQL：python -m scripts.init_knowledge_revisions --output docs/sql/knowledge_revisions.sql。

创建单表：python -m scripts.init_knowledge_revisions --apply。只调用新表的create(checkfirst=True)，不调用metadata.create_all，不执行ALTER或DROP。需要现有依赖表已存在且账号有新表CREATE/外键REFERENCES权限。

## 0. 先建立一个心智模型：四层测试

你的模块有 6 个节点、11 条接口路径、4 张表。一次性全测，出错时根本不知道错在哪。
所以要**分层**，就像装修先验水电、再验瓦工、最后验全屋：

| 层 | 测什么 | 依赖 | 挂了说明什么 | 耗时 |
|---|---|---|---|---|
| **L1 单元层** | 6 个节点的判断规则（剔除达标项、排期不超容量、课程只从库里挑……） | 不连库、不连网 | **我写的业务规则算错了** | < 1 秒 |
| **L2 集成层** | 真实 MySQL 里从诊断跑到考核，4 张表写得对不对 | 要 MySQL | **我和数据库配合错了**（字段、事务、约束） | ~5 秒 |
| **L3 回归层** | 组员既有的架构分层/ORM/技能注册测试 | 大部分不连库 | **我接入公共层时弄坏了别人的东西** | ~9 秒 |
| **L4 接口层** | 服务起得来、11 条接口路径挂上了、没 token 被拦 | 不占端口（ASGI 直连） | **路由/鉴权/启动流程错了** | ~4 秒 |

**排错铁律：从下往上修。** L1 红了先别管 L2——下层错会连累上层，一起红是假象。

## 7. 第七步：怎么看懂"红了"

### 红不是坏事，红是报警器

我特意做了一次演示：把一条断言从 28 改成 30，看它是怎么报的——

```
F                                                              [100%]
_________________________________ test_演示_学时应该等于28 _________________________________

    def test_演示_学时应该等于28():
        total_hours = 28.0
>       assert total_hours == 30.0, f"预期 30.0 学时，实际算出 {total_hours}，请检查排期容量计算"
E       AssertionError: 预期 30.0 学时，实际算出 28.0，请检查排期容量计算
E       assert 28.0 == 30.0

1 failed in 0.22s
```

**读法就三行**：

1. **看 `>` 那一行** —— 出问题的是哪一句断言
2. **看 `E` 开头那几行** —— pytest 直接告诉你"预期多少、实际多少"
3. **看最后一行** —— `1 failed in 0.22s`，几条挂了几条过了

### 常见红的原因对照表

| 现象 | 真实原因 | 怎么办 |
|---|---|---|
| `ModuleNotFoundError: No module named 'pytest'` | 用错 Python 解释器 | 换成 `conda activate py311` 或写全 `anaconda3/envs/py311/python.exe` |
| `RuntimeError: Event loop is closed` | 异步连接跨事件循环复用 | 我模块的测试已用 NullPool 规避；出现在别人用例里就不是你的问题 |
| 整文件 `skipped`，提示"MySQL 测试库不可用" | MySQL 没启动 / `.env` 密码不对 | 启动 MySQL 服务；确认 `.env` 里 `DB_PASSWORD=123456` |
| `Can't connect to MySQL server on 127.0.0.1:3306` | 同上 | 同上 |
| `AssertionError: assert 4 == 5` | 你的规则算出来的数跟预期不符 | 打印中间变量，对照第 2 节的"承诺表"看是哪条规则被破坏了 |
| `IntegrityError: Duplicate entry` | 用例重复跑，脏数据没清 | 用唯一编码（带时间戳）造数据，或重建测试库 |
| `KeyError: 'xxx'` | 返回结构跟你以为的不一样 | `print(resp.json())` 打出来看真实结构，再改断言 |

## 8. 第八步：怎么自己加一条测试（这是真正的能力）

**测试永远是同一个三段式**：造数据 → 调函数 → 断言结果。

### 模板 A：给纯规则加测试（不连库，放 `tests/test_training_logic.py`）

```python
def test_节点1_我的新规则():
    # ① 准备：造一份"假的人才有 3 项能力"，分数故意设成边界值
    abilities = [
        {"dimension": "沟通表达", "current": 80, "required": 82, "weight": 0.2},  # 差 2 分 → 应剔除
        {"dimension": "SQL与数据库", "current": 50, "required": 70, "weight": 0.1},  # 差 20 分 → 应保留
        {"dimension": "项目管理", "current": 78, "required": 85, "weight": 0.25},  # 权重高 → 应 P0
    ]

    # ② 执行：只调一个函数，不连数据库
    gaps = diagnose_gaps(abilities)

    # ③ 断言：把"你认为应该是什么"写死
    assert len(gaps) == 2, "差 2 分的那项应被剔除，应剩 2 项"
    assert all(g["priority"] == "P0" for g in gaps if g["weight"] >= 0.2)

    # 强烈建议：把关键中间值打出来，红了能一眼看懂
    print("实际短板清单：", gaps)
```

跑法（只跑这一条，最快）：

```bash
C:/Users/Windows/anaconda3/envs/py311/python.exe -m pytest tests/test_training_logic.py -k "我的新规则" -v -s
```

> `-k` 按名字筛选用例，`-s` 让 `print` 显示出来。这两个参数是你日常最常用的。

### 模板 B：给真实链路加测试（连库，放 `tests/test_training_service.py`）

```python
async def test_我的新场景(db):
    # ① 准备：用项目自己的 Repository 造数据，别手写 SQL
    talent_id = await _make_talent(db, name="测试员A", abilities=[...])

    # ② 执行：调 service，走真实落库
    plan = await service.generate_plan(db, talent_id=talent_id, weeks=4)

    # ③ 断言：不只断言返回值，还要回查数据库
    assert plan["total_hours"] > 0
    rows = await db.execute(text("SELECT course_id FROM training_plan_item WHERE plan_id=:p"), {"p": plan["id"]})
    assert all(r[0] is not None for rows)   # 每一条都必须挂着库里的课程 id，不许为空
```

**写测试的三个好习惯**（面试也考这些）：

1. **一条测试只验一件事**，名字写清楚"在什么情况下、应该怎样"，别叫 `test_1`
2. **断言要给理由**：`assert x == 2, "差 2 分应被剔除"`，红了不用回头读代码
3. **故意让新测试先红一次**：把预期值改错，确认它真的会报警，再改回来。
   一条从来不会红的测试，等于没写。

## 9. 关于那 3 条已知红灯（不是你的问题，但你要能解释）

跑**全量** `pytest` 时，`tests/test_common_layer.py` 里有 3 条会红：

```
FAILED tests/test_common_layer.py::test_health_ready          - AssertionError
FAILED tests/test_common_layer.py::test_register_login_and_me - AttributeError: 'NoneType' object has no attribute 'send'
FAILED tests/test_common_layer.py::test_super_admin_full_flow - AttributeError: 'NoneType' object has no attribute 'send'
```

**原因（已核实，不是业务代码坏了）**：

1. `test_health_ready` 断言 `data["mysql"] == "up"`，但当前实现返回的是**结构化字典**：
   实际 `{"target": "127.0.0.1:3306/...", "status": "up", "reason": "ok", ...}`。
   我实际请求 `/health/ready`，返回 `200` 且 `status: "up"`、MySQL 连接正常——
   **功能是好的，是这条测试的断言还停在旧版结构上，过期了。**

2. 另两条的 `AttributeError: 'NoneType' object has no attribute 'send'`，
   是 Windows 下 asyncio proactor 事件循环关闭后，连接池里的旧连接仍被复用导致的。

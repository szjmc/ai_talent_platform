## 本组速览与严格边界（开工必读）

- **组别**：`[业务组]`（标签：`标签：[业务组] [P0|P1]`）
- **人力配置**：4 人（BIZ-A 岗位与匹配 / BIZ-B 人才与简历 / BIZ-C 测评与培训 / BIZ-D 文件与审计及联调）
- **本组「做」的范围**：
  1. 8 个待开发模块的 `Repository`（继承 `BaseRepository`）、`Schema`（对齐 `api_document.md`）、`Service`（业务校验、状态机、事务边界、跨组编排调用）、`Router`（挂 `require_permission` 与统一分页响应）。
  2. 为 `[架构组]` 已实现的 `matching_skill`、`resume_skill` 提供无参可调用（`db: AsyncSession | None = None`，内部回退 `session_scope()`）的服务与仓储方法。
- **本组「绝对禁止做」的防重复红线**：
  - ❌ **严禁**新建或破坏性修改 `app/models/*.py`（25 张表 ORM 已完成并通过 135 项 MySQL SQL 断言）；
  - ❌ **严禁**在子 Repository 中重复写 `BaseRepository` 已有的 `get_by_id / paginate / create / update / delete`；
  - ❌ **严禁**自己写人岗匹配打分公式（必须复用 `app.patterns.strategy.MatchStrategyFactory` 与 `app.ai.skills.matching_skill.compute_match_score`）；
  - ❌ **严禁**自己写 PDF/Word 解析器（复用 `[RAG组] app.ai.rag.document_loader.load`）；
  - ❌ **严禁**直接 `import pymilvus`（人才/岗位/试题向量的写入与检索一律调用 `[RAG组]` 的 `EmbeddingService` + `MilvusAdapter`，并捕获 `ExternalServiceError` 确保无 Milvus 时业务 CRUD 不失败）；
  - ❌ **严禁**在业务 Service 中手写 Prompt 直接调大模型生成画像/匹配评语/测评报告/培训推荐（一律通过 `await dispatch("<agent_type>", payload, db=self.db)` 委托 `[Agent组]`）；
  - ❌ **严禁**直接用 `open()` 读写上传文件（一律通过 `FileService` 调用 `[架构组] get_storage()`）。

## 一、标签规范

### 1. 标签格式

每个代码文件的模块 docstring 里加一行（**已全量写回：全部 195 个 `.py` 文件 + 4 个根配置文件均已带标签，本表为唯一登记口径；改标签必须同时改文件头与本表，新增文件漏打标签会被 `tests/test_code_tags.py` 拦截**）：

```python
"""
模块：app/xxx/yyy.py
职责：……

标签：[RAG组] [P0]   依赖：[架构组] BaseLLM、[Milvus] knowledge_vectors
"""
```

- **组标签**：`[架构组]` / `[RAG组]` / `[Agent组]` / `[Vanna组]` / `[Dify组]`（全平台严格分为此 5 组，业务模块按领域垂直归口至各组端到端负责）
- **优先级**：`[P0]` / `[P1]` / `[P2]`
- **依赖标签**（可选）：`依赖：[xx组] 某接口`，跨组依赖必须写明

### 2. 优先级判定规则

| 级别 | 判定标准 | 排期含义 |
| --- | --- | --- |
| **P0** | ① 其他组被它阻塞（契约 / 基类 / 适配器）；② 最小可用链路缺它跑不通；③ 涉及安全（权限、SQL 校验、越权） | 第一优先级，D1–D8 必须完成；延期即整体顺延 |
| **P1** | 核心功能，P0 完成后即可并行开工；不做则功能不完整但可演示 | 第二优先级，D8–D15 完成 |
| **P2** | 增强 / 可选 / 运维向（本地模型、事件总线、图表推断、演示脚本、性能调优） | 有余力再做，D16–D20 或下个迭代 |

### 3. 阻塞关系（谁等谁）

```text
[架构组] AIContext / BaseLLM / BaseSkill / BaseAgent / Auth+Org+File+Audit（底座已就绪 ✅）
   ├──> [RAG组] MilvusAdapter / Embedding / Loader / Retriever + 知识库 + 人才档案 + 简历管理 ──┐
   ├──> [Agent组] GraphBuilder / Workflows / 6 大 Agents + 岗位管理 + 人岗匹配 ─────────────────┼──> 全链路端到端集成
   ├──> [Vanna组] SQLValidator / VannaAdapter / PgSQL ETL + 数据看板 + 在线测评 ────────────────┤
   └──> [Dify组] DifyAdapter / SSE 归一化 + 智能培训与学习督办 ─────────────────────────────────┘
```

**结论**：架构组公共底座与认证/组织样板已 100% 落地冻结；其余 4 组各自拥有完整的「Repository → Schema → Service → Router + AI 引擎」垂直闭环，可并行无阻塞推进。

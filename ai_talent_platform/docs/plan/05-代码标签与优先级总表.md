## 一、标签规范

### 1. 标签格式

每个待实现文件的模块 docstring 里加一行（**本次未改动其他代码，标签集中登记在本文；各组实现时按格式写回文件头部**）：

```python
"""
模块：app/xxx/yyy.py
职责：……

标签：[RAG组] [P0]   依赖：[架构组] BaseLLM、[Milvus] knowledge_vectors
"""
```

- **组标签**：`[架构组]` / `[RAG组]` / `[Agent组]` / `[Vanna组]` / `[Dify组]` / `[业务组]`
- **优先级**：`[P0]` / `[P1]` / `[P2]`
- **依赖标签**（可选）：`依赖：[xx组] 某接口`，跨组依赖必须写明

### 2. 优先级判定规则

| 级别 | 判定标准 | 排期含义 |
| --- | --- | --- |
| **P0** | ① 其他组被它阻塞（契约 / 基类 / 适配器）；② 最小可用链路缺它跑不通；③ 涉及安全（权限、SQL 校验、越权） | 第一优先级，D1–D8 必须完成；延期即整体顺延 |
| **P1** | 核心功能，P0 完成后即可并行开工；不做则功能不完整但可演示 | 第二优先级，D8–D15 完成 |
| **P2** | 增强 / 可选 / 运维向（本地模型、事件总线、图表推断、演示脚本、性能调优） | 有余力再做，D16–D20 或下个迭代 |

### 3. 阻塞关系（谁等谁）

```text
[架构组] AIContext / BaseLLM / BaseSkill / BaseAgent
   ├──> [RAG组] Retriever ──────┐
   ├──> [Agent组] Workflows ────┼──> [Agent组] Agents ──> AgentService
   ├──> [Vanna组] Validator ────┤
   └──> [Dify组] DifyAdapter ───┘
[业务组] Repository ──> Service ──> Router（被以上 4 组共同依赖）
```

**结论**：架构组 `context.py` + `base_llm.py` + `skills/base.py` 延后 1 天，其余 4 组整体顺延 1 天。

# 在线监考 · 反作弊能力说明（切屏 / 远程控制 / 投屏 / 多显示器）

> 归属：`[Agent组]` · 新增于 2026-11-11
> 代码位置：
> `app/ai/proctoring/integrity.py`（判定引擎，纯函数）、`app/services/proctoring_service.py`（编排）、
> `app/routers/proctoring_router.py`（接口）、`app/models/proctoring.py`（三张监考表）、
> `frontend/src/hooks/useProctoring.ts`（浏览器采集）、`frontend/src/pages/ProctoringPage.tsx`（HR 复盘）

## 1. 为什么需要「行为监考」

平台原有的 `app/ai/proctoring/detector.py` 是**视觉检测**（YOLO 检出人/手机/笔记本/书，Haar 人脸回退），
只能回答「摄像头画面里有什么」。而真实面试/笔试作弊绝大多数发生在画面之外：

| 作弊手法 | 视觉检测能否发现 | 行为监考如何发现 |
| --- | --- | --- |
| 切到浏览器/微信搜答案 | ❌ | `visibilitychange` / `blur` → `tab_hidden` / `window_blur` |
| 退出全屏后开小窗 | ❌ | `fullscreenchange` → `fullscreen_exit` |
| 远程代考（ToDesk / 向日葵 / TeamViewer / 微软远程桌面） | ❌ | `blur` 突增 + 共享画面/设备变化 + 心跳异常 + 前端 `remote_control` 上报 |
| 外接投影 / 电视 / 采集卡 / 扩展屏抄答案 | ❌ | `screen.isExtended` 与分辨率启发式 → `multi_display` / `display_changed` |
| 手机投屏（AirPlay / Miracast / 华为多屏协同） | 部分（手机可能出画面） | `display_changed` + `casting` 上报 + 屏幕共享中断 |
| 虚拟摄像头回放录像 | ❌ | `enumerateDevices` 比对 deviceId / label → `unknown_camera` / `virtual_camera` |
| 第三人语音提示 | 部分（多人） | 第二音频输出/外接音频设备 → `audio_output` / `external_audio` |
| 粘贴大段答案 | ❌ | `paste` 文本长度 → `copy_paste` / `clipboard_burst` |
| 关掉页面等时间走完 | ❌ | 心跳超时 → `heartbeat_lost`（服务端推导） |
| 改前端脚本绕过监考 | — | 服务端按心跳与环境快照**独立推导**，且分数只在服务端计算 |

## 2. 架构：三层协作，判定只在一处

```
浏览器（useProctoring.ts）
  ├─ DOM 事件：visibilitychange / blur / fullscreenchange / copy / paste / keydown / devicechange
  ├─ 环境快照：screen.isExtended、屏幕尺寸、摄像头 deviceId/label、时区、时间
  └─ 可选屏幕共享：getDisplayMedia（仅判断「共享是否还在」，抽帧由服务端配额控制）
        │  POST /api/v1/proctoring/{subject}/{token}/heartbeat （每 15s，事件立即入队）
        ▼
服务端编排（services/proctoring_service.py）
  ├─ 归一化事件（integrity.normalize_events，兼容别名/未知事件/毫秒时间戳）
  ├─ 服务端独立推导（心跳中断、环境漂移、强制共享未开、多显示器）
  ├─ 风险打分 + 违规去重（integrity.apply_events）
  └─ 结论（integrity.assess_integrity）→ 写回业务对象
        │
        ├─ HR 复盘：GET /proctoring/sessions、/sessions/{id}（证据链）、POST /sessions/{id}/review
        └─ 候选人：状态条 / 阻断遮罩 / 结果页提示
```

**关键原则：前端只上报「发生了什么」，分数、等级、阻断与否全部由服务端计算。**
候选人即使改脚本删除监听，心跳缺失与环境漂移仍会被判违规。

## 3. 风险分规则（`integrity.RISK_WEIGHTS`）

| 类型 | 分值 | 说明 |
| --- | --- | --- |
| `remote_control` 远程控制 | 40（硬性） | 远程代考的主通道，命中即 `serious` |
| `impersonation` 疑似代考 / `face_mismatch` 人脸不一致 | 40 / 35（硬性） | 视觉 + 行为交叉判定 |
| `casting` 投屏 / AirPlay / Miracast | 30（硬性） | 大屏抄答案 |
| `screen_share_stopped` 停止共享 | 25 | 常与「切换到答案页」同时出现 |
| `no_screen_share` 未共享（强制共享时） | 25（服务端） | 服务端按策略推导，不依赖前端 |
| `virtual_camera` 虚拟摄像头 | 30 | OBS / ManyCam / 采集卡 |
| `virtual_display` 虚拟显示器 | 26 | 虚拟屏放答案 |
| `vm_environment` 虚拟机 | 24 | 沙箱/双系统代考 |
| `multi_display` 多显示器 | 18（服务端） | `screen.isExtended` 或分辨率启发式 |
| `display_changed` 显示器配置变更 | 16 | 基线漂移 |
| `heartbeat_lost` 心断流 | 15（服务端×1.6） | 关页面/断网骗时间 |
| `fullscreen_exit` 退出全屏 | 14 | |
| `tab_hidden` 切标签页 | 12 | 最常见信号，单次只进「观察」 |
| `device_removed` / `device_added` | 15 / 8 | 拔摄像头、插采集卡 |
| `audio_output` / `external_audio` | 20 / 12 | 第二音频输出（耳机/音箱）提示他人 |
| `copy_paste` / `clipboard_burst` | 10 / 6 | 粘贴长文本 |
| `unknown_camera` 摄像头型号变更 | 10 | |
| `network_proxy` 时区/代理突变 | 20 | |
| `proctor_disabled` 开发者工具 | 5 | 尝试篡改前端 |

计分细则：

- **重复衰减**：同类事件第 n 次得分为 `权重 × max(0.35, 1/n)`，既不封顶也不归零；
- **服务端加权**：`source=server` 的事件 ×1.6（关掉前端脚本反而更严重）；
- **封顶 100 分**，单次上报最多 30 条事件；
- **违规去重**：同类风险「恢复前」只记一条违规（HR 看到的是事件而非刷屏），恢复后再犯重新记账。

## 4. 结论与处置

| 分数区间 | level | 建议 | 行为 |
| --- | --- | --- | --- |
| 0 | `clean` | 无需处理 | 正常 |
| ≥15 | `watch` | 继续观察 | 候选人页显示黄色提示条 |
| ≥35 | `review` | 人工复核 | 进入 HR「待处理」列表 |
| ≥60 | `serious` | 追加问询 / 复测 | 报告里置顶观察点 |
| ≥85 | `void` | 建议作废 | **严格模式直接阻断作答** |

硬性违规（`remote_control` / `casting` / `impersonation` / `face_mismatch`）即使分数低也直接抬到 `serious`，
避免「作弊才刚开始就被时间稀释」。严格模式（`PROCTOR_STRICT_MODE=true`）下命中硬性风险 = 立即阻断：
已答内容照常评估（不销毁证据），但 `answer` / `start` 接口会拒绝继续。

**风险分不参与 AI 面试总分与笔试卷面分**，只作为 HR 决策依据（`report.proctoring`、`ExamResult.proctor_*`），
避免「误触一次切屏就扣分」的争议。

## 5. 接口

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/v1/proctoring/config` | `ai_interview:read` | 监考策略（是否强制共享 / 单屏 / 全屏） |
| POST | `/api/v1/proctoring/{subject}/{token}/heartbeat` | 公开（token） | 心跳 + 事件批量上报 |
| POST | `/api/v1/proctoring/{subject}/{token}/snapshot` | 公开（token） | 可疑快照（摄像头/屏幕抽样帧） |
| GET | `/api/v1/proctoring/{subject}/{token}/state` | 公开（token） | 候选人自查（是否被阻断、还缺什么） |
| GET | `/api/v1/proctoring/sessions` | `ai_interview:read` | HR：风险会话分页（`risk_level=flagged` 只看需处理） |
| GET | `/api/v1/proctoring/sessions/{id}` | `ai_interview:read` | HR：证据链（时间线 + 快照 + 结论） |
| POST | `/api/v1/proctoring/sessions/{id}/review` | `ai_interview:manage` | HR：`confirmed` 确认作弊 / `false_positive` 误报 |
| POST/GET | `/api/v1/exam/{assessment_id}/behaviour` | 公开（HMAC 令牌） | 内置考试页（无前端站点）的心跳与状态 |

`subject` ∈ `ai_interview` / `exam` / `interview` / `assessment`。
笔试前端（`/invite/{token}`）用 `exam`，AI 面试（`/ai-interview/{token}`）用 `ai_interview`，
视频面试间用 `interview`，邮件里的后端内置考试页用 `assessment` + HMAC 令牌。

示例（心跳）：

```json
POST /api/v1/proctoring/ai_interview/abc123/heartbeat
{
  "events": [{"type": "visibilitychange", "detail": "切到搜索页", "ts": 1731300000000}],
  "screen_shared": false,
  "display_count": 2,
  "camera_id": "default",
  "virtual_camera": false,
  "timezone": "Asia/Shanghai"
}
→ {
  "state": {"risk_level": "watch", "blocked": false, "warning": "检测到异常行为…"},
  "new_violations": [{"type": "multi_display", "label": "检测到多显示器", "score": 18, "source": "server"}],
  "score": 30.0,
  "level": "watch"
}
```

## 6. 数据表（MySQL）

| 表 | 作用 | 关键字段 |
| --- | --- | --- |
| `proctoring_sessions` | 会话汇总（HR 列表只查这张） | `subject_type/subject_id/subject_token`、`risk_score/risk_level/risk_advice`、`event_counts`、`hard_violations`、`state`（完整状态机）、`last_heartbeat_at`、`blocked_at` |
| `proctoring_events` | 事件明细（时间线复盘） | `session_ref_id`、`event_type/label/detail`、`weight/score_after`、`source`、`occurred_at` |
| `proctoring_snapshots` | 可疑快照（对象存储键） | `session_ref_id`、`source(camera/screen)`、`storage_backend/storage_key`、`trigger_type` |

`ai_interview_sessions` 新增 `proctor_state`（JSON）冗余快照；笔试的 `exam_sessions.proctor_state`
沿用原有 JSON 列写入 `integrity` 子键，因此既有 HR 页面无需改造即可看到异常。

建表：`create_all` 会自动创建三张新表与 `ai_interview_sessions.proctor_state` 列；
**老库升级**需手动执行 `ALTER TABLE`（`create_all` 不会改已存在的表）：

```sql
ALTER TABLE ai_interview_sessions
  ADD COLUMN proctor_state JSON NULL COMMENT '行为监考状态快照（切屏/远程/投屏/多显示器风险汇总）';
```

## 7. 隐私与合规

1. **不存全程录像**：只在命中风险时抽样留存截图，单会话默认上限 15 张（`PROCTOR_SNAPSHOT_MAX_PER_SESSION`）；
2. **屏幕共享可选**：`PROCTOR_REQUIRE_SCREEN_SHARE` 默认 `false`，开启前需在候选人须知中明确告知与取得授权；
3. **上传前压缩**：屏幕帧压到 480px 宽 JPEG，摄像头帧沿用视觉检测的 320px 采样；
4. **删除通道**：快照记录走 `is_deleted` 逻辑删除 + 对象存储物理删除（`ProctoringSnapshotRepository`）；
5. **不做生物特征比对**：`face_mismatch` 仅接受外部（视觉检测/HR）结论，平台本身不建人脸库。

## 8. 降级与容错

| 场景 | 行为 |
| --- | --- |
| `screen.isExtended` 不支持 | 回退「分辨率 + screenX/Y 偏差」启发式，仍能识别大多数扩展屏 |
| `getDisplayMedia` 不支持 / 被拒绝 | 记录 `no_screen_share`，不阻塞作答 |
| 上报网络失败 | 事件留在客户端队列（最多 60 条），下次心跳补传 |
| 监考表未建 / 库异常 | 服务层 try/except，面试与笔试主流程不受影响（仅日志告警） |
| `PROCTOR_ENABLED=false` | 前端不采集，接口返回 `enabled=false`，一切回到未监考状态 |

## 10. 已知边界

- **双设备作弊**（手机看答案、另一台电脑搜）本质无法在浏览器内证明：只能通过摄像头多人/低头、
  音频设备、粘贴长文本等间接信号 + 人工复核；
- iOS / Safari 对 `screen.isExtended`、`getDisplayMedia` 支持有限，移动端主要依赖切屏/失焦信号；
- 恶意用户可彻底禁用 JS 或改脚本：此时**心跳缺失**成为唯一线索，建议考试类场景开启
  `PROCTOR_STRICT_MODE` 并把「心跳中断」纳入人工必查项；
- 风险权重是可运营的策略，不建议在前端暴露分值与阈值（本实现只下发「要不要共享/单屏」）。

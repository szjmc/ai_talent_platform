沙箱测试指南

这份只讲一件事：怎么把沙箱的 11 个接口按正确顺序点通。所有示例响应都是从运行中的 8011 真实采集的， 不是示意。

Sandbox http://127.0.0.1:8011 Swagger /docs 真实服务 8010（对比用） token 内存态 · 重启即失效

0先做 30 秒自检

测试全失败时，八成不是接口坏了，而是「服务没起」或「没带 token」。先确认这两件事。

① 服务在不在

浏览器直接打开
http://127.0.0.1:8011/health

返回 {"code":200,"message":"OK",...} 就是在跑。如果返回 502 或连接被拒，说明进程没起。

② 没起就启动（在项目根目录执行）

bash
D:/0904开班/.venv-match313/Scripts/python.exe -m uvicorn sandbox.mock_api:app --host 127.0.0.1 --port 8011
注意：沙箱和真实服务要分别在项目根目录启动（那里才有 app/ 和 sandbox/）。 token 存在进程内存里，重启一次，之前拿到的 token 全部作废，必须重新登录。

1登录拿 token

除 /、/health、/api/v1/auth/login 外，每个接口都必须带 token。这是最容易漏的一步。

POST /api/v1/auth/login

请求体 application/json
{
  "username": "admin",
  "password": "Admin@12345"
}

响应（真实，每次登录 token 都不同）：

200 OK
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "access_token": "mock.admin.06708f60c0d7",   // ← 复制这一串
    "refresh_token": "mock-refresh.admin.c7bef755",
    "token_type": "bearer",
    "expires_in": 86400,
    "user": { "id": 1, "username": "admin", "real_name": "沙箱管理员",
              "is_superuser": true, "roles": ["super_admin"], "permissions": ["*"] }
  }
}
要复制的是 data.access_token，不是 refresh_token，也不是 token_type。 它长得像 mock.admin.06708f60c0d7，本身不带 Bearer 前缀。

2在 Swagger 里填一次 Authorize

Swagger 顶部有 Authorize 按钮（🔒 图标），填一次，后面所有接口自动带上请求头，不用每个接口重复填。

  1. 打开 http://127.0.0.1:8011/docs。如果之前开过，按 Ctrl+F5 强制刷新，否则会继续用旧的接口描述。
  2. 点右上角 Authorize，弹窗里只有一个 Value 输入框。
  3. 粘贴纯 token，例如 mock.admin.06708f60c0d7。不要自己写 Bearer （Swagger 会自动加；多写了沙箱也会帮你剥掉，但真实服务不一定）。
  4. 点 Authorize → Close。按钮变成带锁的实心状态就成功了。
  5. 之后每个接口直接 Try it out → 填参数 → Execute，参数面板里不会再有 authorization 这一栏。
为什么以前会全失败：沙箱早期版本用的是普通 Header 参数，Swagger 没有 Authorize 按钮， 只能手填 authorization，少写一个 Bearer 加空格就是 401 / 2001「请先登录」—— 看起来像接口全挂，其实只是这一个头的问题。现已改为与真实服务一致的 HTTPBearer。

3.1 JD 解析

POST /api/v1/positions/1/jd/parse

请求体 · jd_text 最少 20 字
{
  "jd_text": "岗位职责：负责企业级AI招聘平台的算法设计与落地，构建人岗匹配模型。任职要求：本科及以上学历，3年以上机器学习经验，熟悉Python与深度学习框架。"
}
200 OK · 关键字段
{
  "code": 200,
  "message": "解析完成（预置画像兜底：ParamError）",
  "data": {
    "channel": "rule_fallback",
    "profile": {
      "job_title": "后端开发工程师",
      "responsibilities": ["负责公司核心业务系统的后端服务开发，参与需求评审与技术方案设计", "..."],
      "required_conditions": [
        { "text": "本科及以上学历", "normalized": "本科",
          "source_span": "本科及以上学历，计算机相关专业", "confidence": 0.9 },
        { "text": "3 年以上后端开发经验", "normalized": "3",
          "source_span": "3 年以上后端开发经验", "confidence": 0.9 }
      ]
    }
  }
}
看到「预置画像兜底」是正常的。沙箱优先跑真实规则解析器，解析不出结构化条件时用预置画像兜底， 这样你任何 JD 都能拿到一份合法结构，方便前端继续往下测。

3.3 确认画像（注意版本锁）

POST /api/v1/positions/1/profile/confirm

请求体 · expected_version 必须等于 3.2 查到的 version
{
  "profile": { "job_title": "后端开发工程师", "responsibilities": ["..."], "required_conditions": ["..."] },
  "expected_version": 2,
  "note": "沙箱确认"
}

成功：200，message 形如「岗位画像 v3 已确认」，版本号 +1。最省事的做法是把 3.2 返回的整个 data.profile 原样贴进 profile。

400 Bad Request · 版本填错时
{ "code": 1002, "message": "画像版本已变化（期望 1，当前 2），请刷新后重试", "data": null }
400 / 1002 不是 bug，是乐观锁在保护你：防止两个人同时确认时后提交的覆盖前一个。 处理办法：重新调 3.2 拿最新 version，再用它作为 expected_version 提交。

3.4 跑匹配

POST /api/v1/matchings/run

请求体
{
  "position_id": 1,
  "strategy": "hybrid",        // hard 只硬过滤 / soft 只打分 / hybrid 先硬后软
  "top_k": 5,
  "with_explanation": false   // 先关掉：不调外部模型，不产生费用与等待
}
200 OK · 真实统计（沙箱预置 5 位候选人）
"stats": {
  "candidates": 5,          // 召回 5 位
  "excluded_by_hard": 1,    // 仅 FAIL 淘汰 1 位
  "unknown": 2,             // 档案缺信息，保留，不淘汰
  "needs_review": 1,        // 需人工复核，保留
  "output": 4               // 最终进入榜单的人
}

榜单结果（按排名）：林一 96.8 PASS → 周珂 87.4 PASS → 吴敏 68.2 UNKNOWN → 郑昊 44.5 NEEDS_REVIEW； 孙楠因硬条件 FAIL 被淘汰并出现在 excluded 里。

单条 item 的关键字段
{
  "talent_id": 1, "talent_name": "林一", "rank": 1, "decision": "PASS", "score": 96.8,
  "dimension_scores": { "skill": 100.0, "experience": 100.0, "education": 100.0, "quality": 88.0 },
  "defaulted_dimensions": [], "data_completeness": 1.0,
  "matched_skills": ["python", "fastapi", "mysql", "redis"],
  "hard_results": [
    { "item": "min_education", "required": "本科", "actual": "本科", "status": "PASS",
      "reason": "学历满足：要求「本科」，实际「本科」", "evidence_id": "EVID-1-1-1" }
  ],
  "explanation_source": null
}
重点看三样：decision 是不是四态之一（PASS / FAIL / UNKNOWN / NEEDS_REVIEW）、 每条判定有没有 evidence_id（EVID-{岗位}-{人才}-{序号}）、excluded 里淘汰原因是否写明硬条件。

4报错对照表

沙箱同时用 HTTP 状态码和业务 code。判断问题时以业务 code 为准，HTTP 码只是分类。

HTTP业务 code提示真实原因怎么改
4012001请先登录 请求里根本没有 Authorization 头（没点 Authorize / 面板被重置） 重新点 Authorize 填 token
4012001登录凭证无效，请重新登录（mock 服务重启后需重新登录） 头带了，但 token 不在内存里：服务重启过、或复制错了（带了 Bearer、复制成 refresh_token） 重新登录，复制 data.access_token
4032004权限不足，无法访问该资源 用小于所需权限的账号（如 viewer 去改画像） 换 admin / hr 账号
4043001接口不存在（mock 仅实现了匹配链路）：GET /xxx 这个接口沙箱没实现（如岗位 CRUD、人才列表、用户管理） 换沙箱已实现的 11 个接口，或去真实服务 8010 测
4043001该岗位还没有匹配记录（position_id=1） 还没跑过 3.4 先跑一次匹配
4001002画像版本已变化（期望 1，当前 2），请刷新后重试 expected_version 与库中当前版本不一致 GET profile 拿最新 version 再提交
422—detail: [{ "type": "string_too_short", "loc": ["body","jd_text"] }] 请求体字段缺失/类型不对，请求根本没进业务 看 loc 指到哪个字段；jd_text 至少 20 字
405—Method Not Allowed 方法用错（如对 /matchings 发了 POST） 跑匹配是 /matchings/run
502—— 本机代理拦截了 127.0.0.1，或服务没起 加 --noproxy '*'；浏览器访问则检查进程
一句话区分 401 的两种文案：「未提供」= 头没发出去（客户端问题）；「无效/过期」= 头发了但 token 不对（登录或重启问题）。

6沙箱的边界（别当成真后端）

实现了什么

11 个接口：/、/health、登录、JD 解析、查画像、确认画像、跑匹配、匹配列表、按岗位查、按人才查、解释。

没实现什么

岗位 CRUD、人才档案读写、用户/角色管理、组织架构、文件上传。访问统一返回 404 / 3001，不是坏了。

数据从哪来

全部来自 sandbox/mock_data.json：1 个岗位、5 位候选人（覆盖四态）、2 版画像、若干解释。改 JSON 重启即生效。

和真实服务的差异

沙箱不连 MySQL、不调 Dify/LLM、不做向量召回，分数与四态判定只用于演示结构，算法结论以 8010 为准。

怎么删掉沙箱：停掉 8011 进程，然后删 sandbox/ 整个目录即可。 主程序对沙箱零依赖（单向依赖 sandbox → app），且 sandbox/ 已在 .gitignore 里， 合代码时不需要任何额外处理。

7一键跑完（不想点 Swagger 就用这个）

同目录下的 run_sandbox_flow.py 会按七步顺序真实请求沙箱，逐步打印状态码与关键字段，最适合「先确认链路通不通」。

执行

python sandbox/run_sandbox_flow.py

换账号或换端口：

bash
python sandbox/run_sandbox_flow.py --user hr --password Hr@123456

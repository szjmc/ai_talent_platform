0前提与自检

真实服务会连 MySQL，比沙箱"重"。跑之前先确认三件事：解释器对不对、库通不通、数据在不在。

① 启动（必须用项目 venv）

bash · 项目根目录
D:/0904开班/.venv-match313/Scripts/python.exe -m uvicorn main:app --host 127.0.0.1 --port 8010
最容易踩的坑：用 anaconda 的 python main.py 启动，会因缺 aiomysql 让所有接口 500（get_db → get_engine → create_async_engine → ModuleNotFoundError）。 判断方法：看 traceback 里 site-packages 路径带 anaconda 就是解释器错了。

真实服务用 JWT（无状态），和沙箱的"内存 token"不同：服务重启不会失效，但 24 小时后会。

3匹配五件套

真实链路：召回 → 硬条件四态 → 维度打分 → 排序 → 证据 → 解释 → 落库。跑一次就有数据可回读。

3.1 执行匹配

POST /api/v1/matchings/run

请求体 · 先关解释，避免调外部模型
{
  "position_id": 1,
  "strategy": "hybrid",
  "top_k": 5,
  "with_explanation": false
}
200 OK · 实测（batch 7db43261…）

  "data": {

6错误对照表（真实服务实测）

HTTP业务码提示原因 / 怎么改
4012001请先登录没带 Authorization 头 → 点 Authorize 填 token
4012001登录凭证无效，请重新登录token 乱填 / 被改过 → 重新登录
4012002登录已过期，请重新登录超过 24h → 重新登录或用 refresh_token 换新
4012003用户名或密码错误登录接口专用，检查账号密码
4032004权限不足，无法访问该资源角色缺权限（如 viewer 改画像）→ 换 admin
4043001岗位不存在（id=999）库里只有 id=1
4043001该岗位还没有匹配记录（position_id=999）先跑一次 /matchings/run
4001002画像版本已变化（期望 1，当前 11），请刷新后重试expected_version 与当前不一致 → 重新查 profile
4001002该岗位尚未确认岗位画像，不能执行正式匹配先去 confirm，再跑匹配
4221001请求参数不合法 / Pydantic detail字段缺失、类型错、jd_text 不足 20 字
500—Internal Server Error先看是不是解释器错了（aiomysql 缺失），再看 traceback
501501xx 模块尚未实现，请对接负责人占位接口，正常现象
一句话记法：2001/2002/2003 是"你是谁"的问题，2004 是"你能干什么"， 3001 是"东西不存在"，1002 是"状态不对"，422 是"传参不对"。

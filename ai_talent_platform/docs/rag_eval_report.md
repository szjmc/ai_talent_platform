全部问题在本次样例中首位命中。不能据此推断真实业务准确率≥95%；语料小、主题区分明显、没有独立人工标注、没有困难负例和多文档答案。8次观测计算的P95实际上是该组最大值，不能作为稳定SLA。

BM25达到本次500ms耗时目标；其他策略未达到。远程Embedding与重排增加端到端时间，但本次未做分阶段埋点，不能把全部耗时归因于网络。生产验收需增加真实脱敏语料、相似制度与版本冲突、无答案问题、部门/角色隔离、并发与冷启动场景。

复现：db312环境中执行 python -m scripts.evaluate_rag。评测会在现有表插入UUID分类测试行，使用真实MinIO、Embedding、Milvus和重排服务，最终清理本次测试行、对象、向量及索引快照；不改表结构。外部模型会产生调用费用。

下一阶段建议：增加真实人工标注集与困难负例；增加分阶段耗时测量；测量查询向量缓存和受限并发召回的收益；在真实规模上评估BM25快照组装开销；优化后用同一评测集复测，避免只调参不留对照。

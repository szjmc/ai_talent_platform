# 三集合七分类存储与查询

## 统一映射

| 分类 | 中文用途 | 集合配置 |
|---|---|---|
| resume | 人才简历 | MILVUS_COLLECTION_TALENT |
| job_description | 岗位说明书 | MILVUS_COLLECTION_KNOWLEDGE |
| assessment | 测评标准 | MILVUS_COLLECTION_ASSESSMENT |
| policy | 企业人才制度 | MILVUS_COLLECTION_KNOWLEDGE |
| training | 培训课件 | MILVUS_COLLECTION_KNOWLEDGE |
| case | 历史项目案例 | MILVUS_COLLECTION_KNOWLEDGE |
| development_plan | 人才培养方案 | MILVUS_COLLECTION_KNOWLEDGE |

默认集合名分别为 talent_chunks、assessment_chunks、knowledge_chunks。

## 使用

- 知识上传 /knowledge/docs/upload 与兼容上传 /files/upload 使用相同分类标识。前者现在也只允许这7种分类。
- /knowledge/retrieve 与 /text2answer 指定 category 时查询对应集合，并添加精确分类过滤；不传时，在当前用户已授权文档涉及的分类内跨集合检索。
- 问题仅向量化一次，各集合COSINE结果全局合并、去重后再进入RRF及可选重排。BM25仍在相同授权文档范围内工作。
- 删除、重试与恢复清理三个集合中该doc_id的本平台命名空间，以清理历史重复残留，不扫描删除其他文档。
- 独立简历业务 /resumes/upload 仍只存原件与业务记录，不自动加入向量知识库；需要向量检索的简历走知识入库接口并选择resume。

## 代码

- core/rag_constants.py：collection_for_category，唯一分类映射。
- adapters/vector_store/milvus_adapter.py：分类写入、跨集合查询、精确分类过滤、三集合删除。
- ai/rag/retriever.py：权限过滤后取得涉及分类，统一合并召回。
- schemas/knowledge.py、services/response_answer_service.py、routers/knowledge_router.py：接口枚举校验。

## 历史数据与验证边界

没有改动MySQL结构或Milvus集合结构，也没有自动迁移远程数据。目标集合需已存在，字段和向量维度必须兼容；不兼容会明确报错。

过去全部写入knowledge_chunks的resume/assessment文档需要单独迁移或重新索引，否则新的语义路由不会在正确目标集合中找到旧向量。job_description现在应存入knowledge_chunks；若已按先前映射写入talent_chunks，同样需要单独迁移或重新索引。其他历史自由文本分类也需要明确映射为上述合法分类。本次不擅自删除或修改这些历史数据。

tests/test_collection_routing.py使用客户端测试替身验证全部7分类写入、分类查询、跨集合去重、三集合清理及非法分类拒绝；不等同于远程三集合联调。远程集合Schema及历史迁移仍需单独验证。

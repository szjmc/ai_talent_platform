# 人才数据决策 Agent · 接口异常边界文档

> 生成时间：2026-11-06 ｜ 覆盖接口：`/agents/chat`、`/agents/report/period`、`/agents/succession`、`GET /agents`、`/analytics/nl2sql`、`/analytics/assessment/summary`
> 所有边界均经真实接口实测验证（正常路径 + 异常路径）。

---

## 一、错误码体系（全平台统一）

| 错误码 | HTTP | 含义 | 典型场景 |
|---|---|---|---|
| 2001 | 401 | 未认证 / 登录过期 | 无 Token、Token 失效 |
| 2002 | 401 | Token 已过期 | 登录超时 |
| 2003 | 401 | 用户名或密码错误 | 登录失败 |
| 2004 | 403 | 权限不足 | 无 `AGENT_USE` 权限 |
| 1001 | 422 | 业务参数不合法 | 周期类型非法 |
| 422 | 422 | Pydantic 字段校验失败 | 缺字段、空值、超长 |
| 3001 | 404 | 资源不存在 | 非法 agent_type |
| 5000 | 500 | 系统内部错误 | 未捕获异常 |
| 5001 | 502 | 外部服务失败 | LLM/Vanna 调用失败 |
| 5002 | 502 | AI 能力异常 | AI 解析失败、超时 |

> 说明：`code` 是业务码（前端看这个），`status_code` 是 HTTP 状态码。二者可不同，前端以 `code` 为准。

## 二、各接口异常边界明细

### 1. POST `/agents/chat`（对话 / 生成报告）

| 场景 | HTTP | code | 触发条件 | 返回表现 |
|---|---|---|---|---|
| 无 Token | 401 | 2001 | 未登录 | `msg=请先登录` |
| 空 question | 422 | 422 | `question=""` | Pydantic 校验失败 |
| 缺 question 字段 | 422 | 422 | 不传 question | Pydantic 校验失败 |
| 超长 question | 422 | 422 | `question` > 500 字 | Pydantic 校验失败 |
| 非法 agent_type | 404 | 3001 | `agent_type="xxx"` | `不支持的 Agent 类型` |
| 无权限 | 403 | 2004 | 无 `AGENT_USE` 权限 | 权限不足 |
| LLM 超时 | 502 | 5002 | 超过 `LLM_TIMEOUT` | AI 执行超时 |
| LLM 返回脏 JSON | 200（降级） | 200 | 第二次推理解析失败 | 走旧版流程，报告仍出，但不落业务元数据 |
| 取不到数据 | 200（拒答） | 200 | `answered=False` | 返回拒答文本，不调 LLM |

**关键降级逻辑**：`chat` 内部有**两次 LLM 调用**（取数→业务推理 + 基座形式调用），任何一次失败都会降级兜底，**绝不阻断主流程**。

---

### 2. POST `/agents/report/period`（周期报告：周/月/年）

| 场景 | HTTP | code | 触发条件 | 返回表现 |
|---|---|---|---|---|
| 无 Token | 401 | 2001 | 未登录 | `请先登录` |
| 缺 report_type | 422 | 422 | 不传字段 | Pydantic 校验失败 |
| 非法周期类型 | 422 | 1001 | `report_type="daily"` | `不支持的周期类型：daily，可选：weekly/monthly/yearly` |
| LLM 超时 | 502 | 5002 | 超过超时 | AI 超时 |

**与 chat 的区别**：周期报告**不需要 question 字段**（系统定时生成，固定模板），非法类型在**路由层**直接抛 `ParamError`（code 1001），不走 Agent。

---

### 3. POST `/agents/succession`（继任方案）

| 场景 | HTTP | code | 触发条件 | 返回表现 |
|---|---|---|---|---|
| 无 Token | 401 | 2001 | 未登录 | `请先登录` |
| 空 post_name | 422 | 422 | `post_name=""` | Pydantic 校验失败 |
| 缺 post_name | 422 | 422 | 不传字段 | Pydantic 校验失败 |
| 超长 post_name | 422 | 422 | > 64 字 | Pydantic 校验失败 |
| 权限范围不足 | 400 | 1002 | `data_scope != all` | `继任方案需全量数据权限` |
| 数据不足（无候选） | 400 | 1002 | 仅有现任无候选 | `数据不足：仅有现任，无候选` |

**特点**：继任方案**不调 LLM**，纯规则引擎计算，因此没有 LLM 超时/脏 JSON 类异常，异常边界更简单可控。

### 5. POST `/analytics/nl2sql`（智能问答，Vanna 组）

| 场景 | HTTP | code | 触发条件 | 返回表现 |
|---|---|---|---|---|
| 无 Token | 401 | 2001 | 未登录 | `请先登录` |
| 空 question | 422 | 422 | `question=""` | Pydantic 校验失败 |
| Vanna 抖动 | 502 | 5002 | Vanna 服务偶发 | 重试即通（已知偶发问题） |

> 该接口属 Vanna 组（3 组）职责，本组只消费其返回的 `insight` 字段，不改动。

---

### 6. GET `/analytics/assessment/summary`（测评统计）

| 场景 | HTTP | code | 触发条件 | 返回表现 |
|---|---|---|---|---|
| 无 Token | 401 | 2001 | 未登录 | `请先登录` |

**返回字段**：`record_count`（测评次数）、`scored_count`（已评分）、`talent_count`（覆盖人才）、`average_score`（均分）、`minimum_score`、`maximum_score`。

## 三、异常边界速查表（按严重度）

| 优先级 | 异常 | 统一返回 | 前端如何处理 |
|---|---|---|---|
| 认证 | 无 Token / 过期 | 401 / code 2001 | 前端自动重新登录 |
| 权限 | 无 AGENT_USE | 403 / code 2004 | 提示无权限 |
| 参数 | 缺字段/空值/超长 | 422 / code 422 | 前端表单校验，提前拦截 |
| 业务 | 周期类型非法 | 422 / code 1001 | 前端只提供 3 个合法选项 |
| 业务 | 继任权限/数据不足 | 400 / code 1002 | 提示具体原因 |
| 资源 | 非法 agent_type | 404 / code 3001 | 前端写死合法类型 |
| 系统 | LLM 超时/失败 | 502 / code 5002 | 提示重试；内部降级兜底 |

## 四、已知问题与风险提示

1. **`data_cutoff`（数据截止）字段不稳定**：它由 LLM 生成，实测两次返回不同值（一次 `2026-12-31（本次盘点数据快照）`，一次 `本次数据快照（未提供具体日期）`）。若需精确时间锚点，应改为后端动态时间戳（参考继任方案的 `generated_at` 实现）。
2. **Vanna 偶发 5002**：`/analytics/nl2sql` 偶发 Vanna 服务抖动，重试即通，属 3 组职责。
3. **周期报告耗时较长**：单份周期报告约 45~55 秒（含两次 LLM 调用），三份全跑会超 3 分钟，建议前端单份触发、加 loading 提示。
4. **GET /agents 是占位接口**：待 AgentService 实现真实分页查询后替换。
